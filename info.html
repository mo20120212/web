Windows Message Notifier — 工程级说明

版本目标平台：net10.0-windows10.0.22621.0。此文档面向工程师，覆盖架构、构建、关键模块说明、运行/调试要点与改进建议。

1. 项目概览

项目为轻量级 Windows 桌面通知工具，提供：

  • 系统托盘控制与未读通知面板（MainWindow / MessageSummaryWindow）
  • 控制中心（SettingWindow）含系统音量与亮度控制
  • SMTC 接入（GlobalSystemMediaTransportControls）用于媒体状态查询与控制
  • 系统通知监听（UserNotificationListener）用于捕获 Toast 并展示

2. 构建与运行

先决条件：.NET 10 SDK、Windows 10/11（带必要的 Windows SDK 支持 Windows.Media / Windows.UI 命名空间）。

dotnet build -c Release
# 可选：dotnet publish -c Release -r win-x64 --self-contained=false

产物位置（默认）：bin\Release\net10.0-windows10.0.22621.0\，可运行 Notifier.exe 或引用 Notifier.dll（TestRunner 用例）。

3. 关键依赖

  • Microsoft.Toolkit.Uwp.Notifications — Toast 通知交互（已在 csproj 中）
  • NAudio — 系统音量接口适配
  • System.Management — 通过 WMI 读取/写入屏幕亮度（硬件）
  • Windows SDK types (Windows.Media.Control / Windows.UI.Notifications.Management)

4. 核心模块与职责（文件）

文件/模块职责
App.xaml / App.xaml.cs应用入口，托盘图标、通知监听器初始化，面板生命周期管理
MainWindow(.xaml/.cs)通知气泡（无焦点 topmost），消息队列、入/退场动画与自动隐藏
MessageSummaryWindow(.xaml/.cs)显示未读通知列表，提供清除和唤醒来源应用

ThemeResources.xaml共享样式、动画与矢量图形（分支已抽取）

5. 主要函数/方法（概要）

按功能模块列出最重要的行为：

  • App.InitializeListenerAsync() — 创建 ToastNotificationListener 并启动轮询（DispatcherTimer）来定期调用 FetchLatestNotificationAsync()
  • ToastNotificationListener.FetchLatestNotificationAsync() — 获取最新通知、去重、解析并通过事件推送到 App
  • SMTCController.InitializeAsync() — 请求 GlobalSystemMediaTransportControlsSessionManager 并订阅 SessionsChanged
  • SMTCController.TogglePlayPauseAsync() — 切换播放/暂停并触发 OnPlaybackStateChanged
  • SettingWindow.TryUpdateMediaUI() — 异步获取媒体信息并在 UI 线程更新 SongTitle/SongArtist/PlayPauseIcon（非阻塞）
  • MainWindow.AddMessage(string) — 解析通知文本、合并分组、显示入场动画并启动隐藏计时器

6. 设计/实现要点（工程级细节）

  • 线程策略：所有直接与 UI 交互的更新使用 Dispatcher.Invoke/BeginInvoke；SMTC 操作通过 Task.Run 封装以避免 UI 线程死锁。
  • 事件驱动：SMTCController 以事件 (OnPlaybackStateChanged/OnSessionChanged) 通知上游；App 使用 OnToastDetected 事件触发 UI 更新。
  • 资源与样式：ThemeResources.xaml 提取了大部分样式/图标，但当前代码中部分窗体仍包含重复资源，建议统一到 Application.Resources。
  • 平台依赖：UserNotificationListener 与 GlobalSystemMediaTransportControls 在部分 Windows 版本或权限设置下可能不可用；需处理权限不足或 API 不可用情形（当前实现多数为静默失败并记录日志）。

7. 已知问题与改进建议（优先级）

  1. 高：把 ThemeResources.xaml 并入 Application.Resources，删除窗体内重复声明，防止资源键冲突与样式不一致。
  2. 高：在 App.xaml 注册 PlayPause 转换器（PlayPauseConverter）或修改 TestRunner 不依赖全局资源。
  3. 中：在 SMTCController 的 CurrentSession_MediaPropertiesChanged 中触发媒体信息的主动刷新（避免只有 PlaybackStateChanged 时遗漏元数据更新）。
  4. 中：改用矢量图标（ThemeResources 中已有 Geometry）替代 emoji，提升 DPI 缩放一致性并简化转换器逻辑。
  5. 中：增加更严格的错误与超时处理（SMTC 与 UserNotificationListener 的调用点），并记录结构化日志以便排查。
  6. 低：将 TestRunner 修改为以项目引用形式引用 Notifier（更健壮），并提供 CI 下的 UI smoke test 脚本（需 Windows 机器）。

8. 调试与本地测试指南

  • 确保 Windows 通知权限已授予：Settings → Privacy → Notifications → 允许应用访问通知。
  • 用 Visual Studio 以 Administrator 身份运行以便测试 WMI 亮度控制与系统级 API。
  • 运行 TestRunner：它会在运行时反射加载 Notifier.dll 并打开 SettingWindow 做交互性 smoke 测试；确保 Notifier.dll 位于 TestRunner.exe 查找路径下（见 TestRunner 工程文件）。
  • 若 SMTC 行为异常，先使用提供的 SMTCController.MonitorChanges() 在单元/手工测试里观察回调和数据。

9. 发布与打包建议

  • 推荐用 dotnet publish -c Release -r win-x64 输出并生成 MSIX/Installer（例如 WiX 或 Inno Setup）以注册 AUMID、安装托盘快捷方式与开机自启。
  • 如需单文件分发，慎用单文件打包以免影响 COM/WinRT 运行时类型查找；建议保留依赖文件目录结构或测试 thoroughly。
  • 签名可执行并设置合适的执行权限。对使用 Windows API 的部分，记录所需最小 OS 版本并在安装向导中展示兼容性信息。

10. 常见故障 & 快速排查

无法接收通知：检查通知权限、并在日志/控制台查看 ToastNotificationListener.InitializeAsync 返回的 Message。
SMTC 无响应：确认目标播放器支持系统 SMTC；尝试重启目标播放器并使用 SMTCController.WaitForSessionAsync() 验证会话可探测性。
亮度写入失败：WMI 对某些外接/虚拟显示器不支持硬件亮度写入，Fallback 为 Gamma 模拟（SetDeviceGammaRamp）。

11. 下一步可交付项（可直行动作）

  • 把 ThemeResources 合并到 App.xaml 并删除窗体重复资源（自动化一次性变更）。
  • 在 App.xaml 注册 PlayPause 转换器并更新 TestRunner，使其不依赖硬编码资源名。
  • 在 SMTCController 的 MediaPropertiesChanged 中新增触发回调，保证媒体元数据及时刷新。
  • 为关键流程（通知监听、SMTC 初始化）添加结构化日志并在 CI 测试脚本里捕获。
